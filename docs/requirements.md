# legacists 要件定義書

この文書は「何のために、何ができればよいか」を管理する。実現方法は[設計書](design.md)、要件の確定は[要件定義Issue #1](https://github.com/kz-oshiro/legacists/issues/1)、利用者向けの案内は[README](../README.md)を正本とする。後工程は[工程別Issue](development.md#開発の進め方)で管理する。

## 目的と利用者

既存のJava・JSP・XHTML・JavaScriptと、XML・プロパティファイルを調査する担当者が、コード間の関連を可視化し、選択したソースをテキストにまとめて開発環境のAIへ渡せるようにする。

初期版では、ファイル単位の関連と根拠を確認し、必要なファイルを手動で選んでTXTへ出力する流れを優先する。変更影響の調査にも利用できるが、メソッド単位の詳細な影響追跡は初期版の対象外とする。

想定する利用環境は導入制約のある社内Windows 11 x64端末。対応はWindows 11のx64のみとし、ARM64は対象外とする。ソースを外部へ送らずに解析し、必要な情報だけを利用者の判断でTXTにまとめる。

AIへ渡す調査TXTには、利用者が選んだソースをそのまま含めてよい。一方、このツールの解析エラーを修正する際には、改修を行うCodexへ解析対象の実ソースを渡せない。作業者が自分の端末で何を確認し、どう対処すればよいかが分かるエラーレポートを初期版の条件に含める。

## 対象ソースの方針と確認状況

| 対象 | 方針・確認状況 |
| --- | --- |
| Java | 調査対象はJava 8前後の可能性があるが、実際の版は未確認。Java 8だけに限定せず、古い構文と新しい構文の双方への対応を希望している。対応する版・構文と初期版で必須にする範囲は未決定 |
| JSP・JavaScript | 解析対象とする。JSPの記法、JavaScriptの構文・ライブラリは未確認 |
| XHTML | 解析対象とする。使用するタグ・参照の記法とフレームワークは未確認 |
| XML・プロパティファイル | ファイル間の参照関係を持つ設定も解析対象とする。参照先が直接書かれている見込みだが、実際の記述は未確認。具体的な形式、参照値の表現と解決規則は未確定。キー・IDを介した参照の有無も未確認 |
| フレームワーク | 独自フレームワークは使っていない見込み。既製フレームワークの有無・種類・版は未確認 |

希望する対応範囲と、合成サンプルで受入条件を確定する範囲を区別する。対象システムの情報が不明な箇所を、特定の版やフレームワークを使用しているとみなして補わない。

## 対象規模

1プロジェクトで調査する対象は数百ファイル程度を想定する。これは性能試験の出発点であり、厳密な入力上限や測定済みの性能を示すものではない。性能基準と測定条件（Q-03）は[性能基準Issue #6](https://github.com/kz-oshiro/legacists/issues/6)で別途確定し、#1のクローズ条件には含めない。固定データと手順の具体化は#2、実測は#4で扱う。

## 機能要件

| ID | 利用者ができること | 受入条件案 |
| --- | --- | --- |
| R-01 | プロジェクトのフォルダを選び、解析対象のファイルを探す | 名前・相対パスの検索とフォルダツリーから起点を選べる。読めない資源と除外範囲が分かる |
| R-02 | Java・JSP・XHTML・JS・XML・プロパティファイルにまたがる関係を調べる | 対応すると定めた構文・設定について、固定サンプルから期待する関係を抽出できる。XML・プロパティファイルに記述された参照関係も含める。未対応・未解決も確認できる |
| R-03 | 選んだファイルから、関連するファイルをたどる | ファイルをノードとして参照元・参照先を展開できる。対応範囲で定めた関係の種類を区別できる |
| R-04 | プロジェクト全体の概要をグラフで把握する | フォルダ・パッケージなどの単位で集約し、集約対象から個別資源へ移動できる |
| R-05 | 関係の根拠となるソースを確認する | グラフの関係からファイル・位置・抜粋を確認できる。ソースを閲覧時に実行しない |
| R-06 | 多数の関係がある共通資源を調べる | 集約・絞り込み・段階的な展開で調べられる。表示を省略しても解析結果から関係を失わず、省略の有無が分かる |
| R-07 | 調査対象を選び、AIに渡すTXTへ出力する | ツリーやグラフから一件ずつ手動選択し、ファイル一覧・相対パス・ソース全文・関係・根拠・解析の限界を確認して保存できる。関連ファイルを自動追加せず、ソースをマスク・要約・省略しない。UTF-8で出力し、800KBを基準に分割できる |
| R-08 | 解析エラー時に、何を確認してどう対処すればよいかを把握する | エラー番号・処理段階・対象ファイルと位置・影響、判明した原因と原因候補、具体的な確認項目・対処手順を、人間が読めるエラーレポートとして表示・TXT保存できる。対処できない場合も次に確認・報告する情報を示し、Codexへ実ソースを提出することを解決の前提にしない |
| R-09 | 文字コードが異なるソースを正しく読む | 初期版の入力はUTF-8・SJIS系（CP932を含む）に限定し、ファイルごとに文字コードを判定・表示し、手動指定で修正できる。ほかの文字コードは追加しない。復号できない内容を黙って置換せず、元ファイルは変更しない |
| R-10 | 設定の保存先を管理する | 選択状態・文字コード指定・除外設定をユーザー用データ領域へ保存する。設定画面で既定と現在の保存先を確認・変更でき、ツールの保存データを削除できる。ソース本文と解析結果は永続保存しない |
| R-11 | 変更したソースを手動で再解析する | 更新操作で読み直す。TXT出力前に解析時点からの変更を確認し、変更があれば再解析を案内して、古い関係と新しい本文を混在させない |

初期版の関係グラフはファイル単位とする。クラス・メソッド単位への掘り下げは将来の拡張候補とする。ファイル間の関係について根拠のソース位置を確認する機能（R-05）は初期版にも含める方針を維持する。

AI向け調査TXT（R-07）と、解析エラー時の作業者向けエラーレポート（R-08）は初期版の必須機能とする。調査TXTにはソースをそのまま出力する。エラーレポートは、実ソースを受け取れない改修担当へも状況を伝えられるよう、ソース本文・抜粋・設定値を添付せずに確認箇所と手順を示す。相対パス・ファイル名・クラス名は含めてよい。この扱いを通常の調査TXTへ適用しない。

参照元と参照先を左右に分けるバタフライ表示、一覧表との切替、独自の業務分類は候補とする。初期版の必須機能にはまだ固定しない。

## 読み込み・TXT出力・保存

- 入力はファイルごとに判定する。SJIS系にはWindowsのCP932を含める。自動判定を修正できるようにし、復号失敗は解析失敗と区別する。
- 調査TXTは通常一つとし、既定上限800KB（800,000バイト）を超える場合は連番で分割する。UTF-8変換後の見出し・関係情報を含む実容量で判定し、上限は設定で変更できる。BOMなしを設計上の既定とする。
- 分割はソースファイルの境界を優先する。一つのソースが上限を超える場合は行単位を基本に分割し、相対パス・行範囲・続きであることを明記する。本文は欠落させない。
- 復号できた選択ソースは構文解析に失敗しても出力対象にでき、「未解析」とエラーの所在を示す。復号できないファイルは出力できないことを明示し、置換文字で全文を作らない。
- エラーレポートもUTF-8で保存する。設定とアプリが作る作業データはユーザー用データ領域で管理し、削除機能は解析元ファイルや利用者が保存したTXTを対象にしない。

## 動作・品質要件

| ID | 要件 | 受入条件案 |
| --- | --- | --- |
| N-01 | Windows 11 x64で単一EXEを起動できる | GitHub Releaseの配布ZIP内はx64用実行EXE一つだけとし、EXEだけを移動しても起動できる。ARM64は対象外。隣接するDLL・CMD・README・設定ファイルを要求しない。既存WebView2を利用し、追加インストール・管理者権限・起動時のダウンロードを要求しない |
| N-02 | 解析と閲覧はオフラインで完結する | アプリの画面・解析資材をEXEに内包し、解析対象・検索語・利用状況を外部へ送信しない。AIへの直接接続を必要としない |
| N-03 | 元のソースを保護する | 解析対象のコードやプロジェクトのビルドを実行せず、元ファイルを変更しない。TXTは利用者が指定した出力先、設定はR-10の保存先に保存する |
| N-04 | 静的解析の確定範囲と限界を伝える | 確定した関係・候補・未解決を識別でき、根拠と未解決理由を確認できる。検出できない関係を「存在しない」と断定しない |
| N-05 | 数百ファイル程度のプロジェクトで調査を続けられる | 進捗・キャンセル・解析エラーを扱える。時間・メモリ・画面応答の基準と測定条件は#6で確定し、#4で固定データを使って測定する |
| N-06 | 解析CoreをGUIから独立して利用できる | CoreがTauri・Vue・画面状態に依存しない。GUIを起動せずに同じ解析契約を試験できる |
| N-07 | 実ソースを改修担当へ渡せなくても、作業者が解析エラーを切り分けられる | エラーレポートだけで確認箇所・手順・影響と次の行動が分かる。ソース本文・抜粋・設定値を含めず、相対パス・クラス名・位置、アプリ版・実行環境などで対象と状況を特定する。原因不明は不明と示し、作業者の確認結果と公開可能な合成データを基に追加調査を進められる |

対応はWindows 11 x64、入力文字コードはUTF-8・SJIS系に決定した。性能値は#6、対応言語・フレームワークの範囲は#1、文字コード判定の詳細は#2で確定する。配布は単一EXEのZIPとし、既存WebView2を利用する。利用者から同じ端末でdocs-searchが動作するとの情報はあるが、legacistsの起動・製品検証の証拠はまだない。

## 初期版の対象外案

メソッド単位の詳細な影響追跡は対象外として決定した。以下は引き続き対象外案とする。

- ソース編集、リファクタリング、JavaやJSの実行、プロジェクトのビルド。
- AIサービスへの自動送信、サーバ運用、複数人での共同編集。
- VS Code拡張としての配布、Windows以外への配布。
- 動的呼び出し・リフレクションを含む、全実行経路の完全な再現。
- 高度な制御フロー・データフロー解析。必要性を確認して別案件で扱う。

これらは今回の整理における範囲案であり、将来の対応を禁止するものではない。
